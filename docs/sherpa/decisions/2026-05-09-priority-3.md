# Priority 3 design decisions

Date: 2026-05-09
Context: Priority 3 (Stage-2 prep adapters — Aerodrome SWAP, Morpho LEND, Aave LEND)

## 1. Address handling: Limitless pattern, applied uniformly
- New `Address | undefined` exports in @sherpa/safety: `AERODROME_ROUTER_ADDRESS`,
  `MORPHO_BLUE_ADDRESS`, `AAVE_V3_POOL_ADDRESS`. All `undefined` until Stage 2 wires real values.
- `isAllowlisted` checks each when defined — no need to mutate `ALLOWED_CONTRACTS` to flip them on.
- Each adapter throws a typed `*NotConfiguredError` from `buildTx` until its address is set.
- Rejected: hard-coding mainnet addresses with a chain gate. Stage 4 audit owns the mainnet flip.

## 2. Intent union: add LEND, defer SWAP wiring
- `Intent` already had SWAP from earlier; LEND added now (type-only).
- Parser stays UNKNOWN for SWAP/LEND prose until Stage 2's parser work.
- `VALID_INTENTS` in parser.ts updated so LLM fallback can return LEND once prompts
  include it.

## 3. SWAP quote comparison: deferred to Stage 2
- Both Uniswap and Aerodrome adapters expose `quote()` with compatible shapes
  (`amountInBaseUnits`, `amountOutBaseUnits`, `route`).
- A `compareSwapQuotes()` helper would prematurely commit to a Stage-2 routing
  policy — explicit choice deferred to the SWAP executor PR.

## 4. LEND adapter shape: per-protocol, not a shared interface
- `MorphoLendParams` requires `marketParams` (Morpho's `(loanToken, collateralToken,
  oracle, irm, lltv)` tuple); `AaveLendParams` doesn't (Aave routes by asset).
- A single shared `LendParams` would have to make `marketParams` optional, which
  removes the per-protocol type safety.
- Stage-2 LEND planner is responsible for translating user intent into the
  adapter-specific shape.

## 5. APY values: stubbed, configurable via test seam
- `STUB_SUPPLY_APY_BPS` (Morpho 450, Aave 380) are illustrative — they let the
  display string be exercised in tests without a live RPC tier.
- `MorphoConfig.stubSupplyApyBps` / `AaveConfig.stubSupplyApyBps` exist for tests
  to assert APY-dependent display formatting deterministically.
- Real APY reads land in Stage 2 with the rest of the LEND executor work.

## 6. Verify selectors: computed dynamically via viem
- `toFunctionSelector(abi[i])` at module load time. Avoids hard-coding magic
  hex strings (a previous PR already had to fix one wrong guess).
- The Aerodrome `swapExactTokensForTokens` selector is route-shape-specific —
  computing it from the ABI guarantees the adapter's verify matches what
  buildTx actually produces.

## 7. Ring 1 trust model under `extras`
- Configured adapters (`createAerodrome({routerAddress})` etc.) pass their
  vouched address as `extras` to `assertAllowlisted`, mirroring 2.1's Limitless
  pattern.
- Default exports (with no override) hit the `extras = []` path, so production
  Ring 1 trust is unchanged.
- Once Stage 2 wires real addresses into the safety constants, the `extras`
  parameter is no longer needed by production code — it stays as a test seam.

## Carry-overs from PR #8 review (already shipped in PR #8)
- Verbless SEND vs SWAP collision: `parseDeterministic` bails to UNKNOWN with
  confidence=0 when the captured recipient is a known asset symbol
  (USDC/USD/ETH/WETH/BTC/WBTC). Test in core/index.test.ts.
- Spend-cap per-process limitation: documented in
  `packages/llm/src/spend-cap.ts` JSDoc with the Vercel-Hobby-vs-horizontally-
  scaled note.
