# Devlog: Stage 8 P1 — Security Hardening

**Date:** 2026-05-15
**Stage:** 8 P1
**Author:** Sherpa

## What shipped

### Parser (core)
- `SECURITY` intent with deterministic parsing for:
  - `setup multisig wallet` → `securityAction: 'multisig'`
  - `connect ledger wallet` → `securityAction: 'hardware'`
  - `check my security status` → `securityAction: 'status'`
  - `add 0x1234 to my whitelist` → `securityAction: 'whitelist'`
- Regex patterns in `parser.ts:138-142`
- Slots: `securityAction`, `securityTarget`

### Multi-sig module (tools)
- `createMultisig(config)` — stub returns zero address
- `getMultisigTransactions(address)` — stub returns empty array
- `buildSubmitCall(to, value, data)` — builds submitTransaction calldata
- Types: `MultisigConfig`, `MultisigTransaction`, `HardwareWalletInfo`, `SecurityDeps`

### Tests
- `packages/core/src/index.test.ts` — 4 SECURITY parser tests
- `packages/tools/src/security/multisig.test.ts` — 3 multi-sig module tests

### Documentation
- Decision record: `docs/sherpa/decisions/2026-05-15-security-stage-8.md`

## Integration notes
- All security actions are stubbed for V1 (no real on-chain execution)
- Multi-sig uses a minimal ABI for submitTransaction, confirmTransaction, executeTransaction
- Hardware wallet pairing returns stubbed info; real integration requires WalletConnect/USB SDK
- Whitelist is client-side only; future: on-chain whitelist contract with time-locks
