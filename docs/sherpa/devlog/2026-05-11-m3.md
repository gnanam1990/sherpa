## Cross-domain notes

### M1 (backend) — schema delta to be aware of

No code change required: existing `createAuditLog({userAddress, intent,
planHash, submittedAt}, store)` calls still compile and run, and the in-memory
store is unchanged. **However, the audit_log table has both `intent`/`plan_hash`
columns AND `parsed_intent`/`plan` JSONB columns**, intentionally. The two
representations are denormalized:

- `intent` (TEXT) and `plan_hash` (TEXT) come from the legacy
  `CreateAuditLogInput` fields.
- `parsed_intent` (JSONB) and `plan` (JSONB) hold the full structured shapes.
- Today only `apps/api/src/server.ts` populates the JSONB columns. If M1's
  executor ever creates audit rows directly (instead of through the API
  layer), keep both in sync — the JSONB columns are the source of truth for
  Stage 2 dashboards and replay tooling.

Action for M1: nothing to do this week, but flag if a Stage-2 executor path
needs the JSONB shape and we should split the responsibility differently.

### M2 (frontend) — no surface change

`/api/execute` response is unchanged: `{ ok, auditLogId, planHash, card }`.
