**Date:** 2026-05-15
**Stage:** 8 P4
**Author:** Sherpa

## What shipped

### Cross-chain Orchestrator (tools)
- `orchestrate(steps)` — builds `OrchestratedTx` from ordered `CrossChainStep[]`
- `validateOrchestration(steps)` — enforces min 1, max 5 steps; returns string[] of errors
- Status lifecycle: `pending → bridging → executing → completed | failed`
- `totalTime` computed as sum of all step `estimatedTime` values

### Types
- `CrossChainStep` — chain, action, protocol, estimatedTime
- `OrchestratedTx` — steps[], totalTime, totalFee, status
- Exported from `packages/tools/src/cross-chain/index.ts`

### Tests
- `packages/tools/src/cross-chain/orchestrator.test.ts` — 3 orchestrator tests (new file):
  - `orchestrate` returns correct step count and total time
  - `validateOrchestration` rejects empty steps
  - `validateOrchestration` rejects >5 steps

### Documentation
- Decision record: `docs/sherpa/decisions/2026-05-15-cross-chain-stage-8.md`

## Integration notes
- Orchestrator is a stub for V1; real execution would interact with bridge contracts
- Fee aggregation is placeholder (0n); real fees come from router quotes
- Step validation is intentionally strict (max 5) to prevent overly complex flows
- Future: parallel execution for independent chain steps, retry on bridge failure
